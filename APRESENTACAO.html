Criterio 1 · APIs REST e CDI

Criar não é só salvar

Olha o contrato

  • Cada serviço tem seu próprio módulo Quarkus.
  • POST /boletos cria um recurso e responde 201 + Location.
  • O recurso entrega a regra para EmissaoService via CDI.
  • Contratos e erros tambem testados para os outros endpoints.

Na prática: 201 diz “nasceu um recurso”; Location aponta onde encontrá-lo.

@POST
@RolesAllowed(SecurityRoles.OPERADOR)
public RestResponse<BoletoAceito> emitir(
    @Valid EmitirBoletoRequest request,
    @Context UriInfo uriInfo) {
  BoletoAceito aceite = service.aceitar(request);
  URI location = uriInfo.getAbsolutePathBuilder()
      .path(aceite.identificador().toString()).build();
  return RestResponse.ResponseBuilder
      .<BoletoAceito>created(location)
      .entity(aceite)
      .build();
}

Criterio 3 · Hibernate ORM com Panache

Duplicou? O banco barra.

@ApplicationScoped
public class EmissaoRepository
    implements PanacheRepositoryBase<BoletoEmissaoEntity, UUID> {

  public Optional<BoletoAceito> buscarPorChave(
      String convenio, String numeroControleCliente) {
    return find("convenio = ?1 and numeroControleCliente = ?2",
        convenio, numeroControleCliente)
        .firstResultOptional()
        .map(BoletoEmissaoEntity::toDto);
  }

  public void salvar(BoletoAceito boleto) {
    persist(BoletoEmissaoEntity.from(boleto));
  }
}

Quem protege a regra?

  • O repositório deixa banco e regra de negócio em lugares diferentes.
  • H2 separado para cada serviço e perfil.
  • Chave única: convênio + número de controle.
  • Testes exercitam criacao, leitura, duplicidade e remocao.

Detalhe legal: a checagem no código ajuda; a constraint no banco fecha a corrida entre requisições.

Criterio 2 · REST Client + Fault Tolerance

Se o Registro tossir, o Emissor reage

Quatro cinturões de segurança

  • Timeout 500 ms: limita a espera pelo servico dependente.
  • Retry 2: tenta de novo em falha transitória.
  • Circuit breaker: interrompe chamadas apos 4 falhas observadas.
  • Fallback: converte indisponibilidade em erro controlado 503.
  • Repetir é seguro: o UUID torna o registro idempotente.

4xx inesperado do registro vira 502 e nao e repetido.

@Timeout(500)
@Retry(maxRetries = 2,
       abortOn = RegistroRejeitadoException.class)
@CircuitBreaker(requestVolumeThreshold = 4,
       skipOn = RegistroRejeitadoException.class)
@Fallback(fallbackMethod = "registroIndisponivel",
       skipOn = RegistroRejeitadoException.class)
public void registrar(UUID identificador) {
  client.registrar(new RegistrarBoletoCommand(identificador));
}
